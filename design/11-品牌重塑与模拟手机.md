# 品牌重塑 · 模拟手机升级

> 对应 `dist/EchoFlow-v2.5-星语-模拟手机.apk`（6.17 MB）
> 本轮三件事：**换名换图标**、**朋友圈内置进手机**、**把手机做得像真手机 + 加新功能**

---

## 一、品牌重塑

### 1.1 新名字：星语

| | 旧 | 新 |
|---|---|---|
| 中文名 | （无） | **星语** |
| 英文名 | EchoFlow | EchoFlow（保留为副名） |
| 包名 | `com.echoflow.chat` | 不变（改包名会导致老用户数据丢失） |
| Slogan | Android 原生 · AI 流式对话 | **与你有关的，都会被记住** |

**命名理由**：
- 「星」呼应设计系统的「星轨 Star-Rail」与神社的「星念卡」，是这套视觉语言的内在线索
- 「语」直指对话本身
- 两个字，好念、好记、不像工具名

**包名为什么不动**：`applicationId` 一旦改变，系统会视为另一个应用，用户已装版本的
角色卡、聊天记录、记忆全部丢失。品牌名和包名本来就该解耦。

### 1.2 新图标

用 AI 生成后加工：深靛紫渐变底 + 两个交叠的对话气泡，其中一个的角**旋成一个四角星** ——
「对话变成记忆」的视觉表达，正好对上 slogan。

产出方式：

| 文件 | 尺寸 | 用途 |
|---|---|---|
| `mipmap-{m,h,xh,xxh,xxxh}dpi/ic_launcher.png` | 48/72/96/144/192 | 传统图标 |
| `mipmap-anydpi-v26/ic_launcher.xml` | 自适应 | Android 8+ 自适应图标 |
| `drawable/ic_launcher_fg.png` | 432×432 | 自适应前景（含 66% 安全区） |
| `drawable/ic_launcher_bg.xml` | 矢量 | 自适应背景渐变 |
| `drawable/app_icon.png` | 192 | 应用内使用 |

自适应图标的前景做了**安全区处理**：图形只占中间 62%，四周留白，
这样无论系统裁成圆形、方形还是水滴形，核心图形都不会被切掉。

### 1.3 界面里的旧名字

替换了 6 处硬编码的「EchoFlow」为 `@string/app_name`，改名字以后只需动一处。

## 二、模拟手机

### 2.1 三个层次

之前只有「微信风的会话列表」，那只是**一个应用**，不是**一台手机**。
这轮补成三层：

```
┌─ 系统层 ─────────────────────────────────────┐
│  状态栏：真实时间（每秒刷新）· 真实电量（BatteryManager）  │
│          信号格数（按分钟做种子，缓慢变化，看着像真的）      │
│          网络制式（5G/4G 轮换）                          │
├─ 桌面层 ─────────────────────────────────────┤
│  时钟小组件（H:mm，实时走）· 日期                     │
│  8 个应用图标（4×2 网格）· 未读角标                    │
│  Dock 毛玻璃（4 个常用）· 页面指示点                    │
├─ 内容层 ─────────────────────────────────────┤
│  微信 · 朋友圈 · 角色库 · 神社                       │
│  日程 · 电话 · 设置 · 关于                          │
└──────────────────────────────────────────┘
```

### 2.2 状态栏是真的

不是写死的装饰：

```java
PhoneSystem.clock()      // SimpleDateFormat(HH:mm)，每秒刷
PhoneSystem.battery(ctx)  // registerReceiver(null, ACTION_BATTERY_CHANGED) 读真实电量
PhoneSystem.charging(ctx) // 充电中显示 ⚡
PhoneSystem.signalBars()  // (now/60000) % 5，同一分钟稳定、跨分钟变化
```

实测截图里显示 `09:41 / 4G / ▁▃▅▇ / 100 / ▮` —— 时间与电量都是设备真实值。

### 2.3 朋友圈内置进手机

新增 `PhoneMomentsActivity`，与独立的 `PostsActivity` 共用 `PostStore`，
两个入口看到同一批动态，但手机版有：

- 真实状态栏
- 微信风顶部栏（返回 / 标题 / 📷）
- **封面图 + 我的头像**（微信朋友圈的经典结构）
- 每张卡配一张场景图，按角色固定分配（爱丽丝=雨夜、凛=校园、白夜=手水舍…）
- **点角色头像/名字 → 进她的手机聊天**（而不是主聊天）
- 长按删除、♡ 点赞
- 动态生成的 prompt 里明确写了「不要写动作描写 —— 朋友圈就是打字」

### 2.4 新功能一：她的今天（日程）

`PhoneScheduleActivity` + `Schedule`。

每个角色有一张作息表，**高亮当前时段**：

```
月铃 · 今天
  此刻
  天亮前离开
  白天找不到她
  09:30 · 有空

  20:00  出门            灯是她唯一带的东西
  22:00  在老城区走       沿着她说的那条路线
  02:00  在路口站着       不做什么，就是在
  05:00  ● 天亮前离开     白天找不到她      ← 当前
```

**这不只是展示**。日程会注入 Prompt：

> 现在是 14:20，你正在「剑术训练」（这个时段回复会很慢）。
> 这个时段你在忙，回复会更短、更可能让对方等一下。

所以同一个角色，上午 9 点和下午 3 点的回复长度是不一样的。
这是「她有自己在过的生活」从设定变成了机制。

6 个内置角色各有独立作息（爱丽丝巡夜到 23:30、凛早自习会补觉、
白夜凌晨 4 点观测、洛可 22:00 关店但灯留着…），用户可自行修改。

### 2.5 新功能二：电话

`PhoneDialerActivity` + `VoiceCallActivity`。

拨号盘列表里，每个人的副标题是**此刻在做什么**：

```
艾莲   此刻：开门 · 可能不方便接 · 平静
洛可   此刻：开店 · 平静
爱丽丝  此刻：换班交接 · 可能不方便接 · 平静
```

点绿色按钮 → 通话界面：呼叫中 → 接通 → 计时 → 她的字幕逐字出现 → 挂断。
通话结束后整段对话**写入手机聊天记录**，并跑一遍状态分析（记忆/关系/情绪）。

> **诚实说明**：这里没有真正的实时音频流（那需要 STT + TTS + 音频通道，是独立的大工程）。
> 当前是「**通话式文本对话**」：体验上是通话，数据上是聊天。
> 好处是在没有 TTS 的前提下也能用；将来接上 TTS，只需把字幕替换成语音播放，界面不用改。

### 2.6 桌面角标

微信显示「有聊天记录的角色数」，朋友圈显示「动态条数」，
用红色圆形角标（`#FA5151`），与真手机一致。

## 三、修掉的一个崩溃（原工程遗留）

### CardEditActivity 打不开

```
java.lang.ClassCastException:
  com.google.android.material.textview.MaterialTextView
  cannot be cast to android.widget.ImageView
    at CardEditActivity.onCreate(CardEditActivity.java:54)
```

**根因**：`activity_card_edit.xml` 里把 `avatar_preview` 声明成了 `<TextView>`，
但 Java 侧字段是 `ImageView`，并且会调用 `setImageBitmap()`。

```xml
<!-- 错误（原 v3.0 源码） -->
<TextView android:id="@+id/avatar_preview" ... android:src="@drawable/app_icon" />

<!-- 正确 -->
<ImageView android:id="@+id/avatar_preview" ... android:scaleType="fitCenter" />
```

这是**原工程就存在的 bug**，之前没暴露是因为没人从「角色库 → 编辑」这条路走过。
这轮我给首页加了「角色库」入口，用户一步就能点到，于是炸了。

**教训**：给别人加新入口时，要把那个入口背后的**所有路径**都点一遍。
新入口的价值恰恰在于让原本到不了的代码被执行到 —— 包括那些有 bug 的。

## 五、踩坑记录

### 图标全渲染成白圆

第一版桌面图标用 `layer-list` + `<shape>` 实现，结果 8 个图标全是白色圆形。

**原因**：`layer-list` 的 `<item android:width/height>` 属性**只对 `<bitmap>` 生效**，
对 `<shape>` 无效 —— 内层 shape 会撑满整个容器，把底图完全盖住。

**修复**：改用 **vector drawable**（`<vector>` + `<path>`），
所有图形用 pathData 描述，缩放无失真，且不受 density 影响。
新建 `tools/audit-view-types.ps1` 就是这次教训的产物（虽然它本身有 bug，见下）。

### PowerShell 写文件带 BOM 导致编译失败

用 `Set-Content -Encoding utf8` 改写 Java/XML 时会写入 UTF-8 BOM，
Java 编译器报 `非法字符: '\ufeff'`。

**修复**：批量检测并剥掉 BOM：

```powershell
$b = [System.IO.File]::ReadAllBytes($f)
if ($b[0] -eq 0xEF -and $b[1] -eq 0xBB -and $b[2] -eq 0xBF) {
    [System.IO.File]::WriteAllBytes($f, $b[3..($b.Length-1)])
}
```

**以后写文件统一用 `[System.IO.File]::WriteAllText($path, $text, [Text.UTF8Encoding]::new($false))`。**

### 审计脚本本身写错了

我写了个脚本想自动找「布局类型 vs 代码类型」冲突，结果它的正则匹配不到属性顺序不同的
`<View ... android:id=...>`，导致 `$decl` 是空的，于是**把 41 个正常的 findViewById
全报成了冲突**。

**结论**：扫描工具报出的问题必须**人工抽样验证**，否则比没有工具更危险 ——
满屏假阳性会让人忽略真信号。这个脚本留在 `tools/` 但**不建议直接采信**。
