## 一、先说那个"模型不存在"的 bug

这个不是你用错，是**配置系统有两套，读写对不上**。

### 症状

- 设置页填好 API → 保存 → 再进去看，**又是空的**
- 有些页面能用，有些页面报"模型不存在"

### 根因

| | 读 | 写 |
|---|---|---|
| 设置页回填 | `echoflow_config`（老） | — |
| 设置页保存 | — | `echoflow_provider`（新） |
| 手机 / 聊天 / 通话 | `echoflow_provider` | |
| **神社 / 日记 / 信笺 / 胶囊 / 占卜** | `echoflow_config`（老） | |

两个问题叠在一起：

1. **回填读老、保存写新** → 每次进设置页看到的都是默认值，
   一保存就把刚填的覆盖掉
2. **保存只写新** → 神社那几个页面读老地方，永远拿不到配置

所以"原来用的就是这个 API"是真的——**它在某些页面能工作，在另一些页面报模型不存在**。

### 修法

**1. 回填读同一个 store**

```java
// 改之前：读 ChatStore（老）
this.inputBaseUrl.setText(ChatStore.getBaseUrl(this));
// 改之后：读 ProviderStore（新，也就是保存时写的那个）
this.inputBaseUrl.setText(ProviderStore.baseUrl(this));
```

**2. 保存时双写**

`ProviderStore.save()` 里同步调 `ChatStore.saveConfig()`，
让还在读老配置的五个页面也能拿到。

**3. `effectiveBaseUrl/Model` 加了回退链**

新配置 → 老配置 → 默认值，不会再返回空。

### 实测

| 测试 | 结果 |
|---|---|
| 填入云端 API 并保存 | ✅ |
| 重进设置页回填 | ✅ 显示真实值 |
| 老 store 是否同步 | ✅ `echoflow_config` 里有 base_url + model |
| 手机聊天调通 | ✅ 发 "hi" → 回「嗯，刚打烊。」 |
| 神社解读调通 | ✅ 正常生成 |

## 二、"手机外对话没了"——其实是被藏起来了

### 真凶

首页那个「开始对话」按钮，**布局里的 id 叫 `btn_cards`**（历史遗留，和卡片没关系），
而它绑的行为是：

```java
findViewById(R.id.btn_cards).setOnClickListener(v ->
        startActivity(new Intent(this, CardListActivity.class)));   // 跳角色库
```

所以路径是：**首页 → 角色库 → 点角色 → 角色详情页 → 点聊天**，四步。

而真正能直接进角色扮演聊天的入口，只有两个隐蔽的地方：

- 角色详情页里一个按钮
- **手机模式聊天右上角那个 `···` 角标**

`CardChatActivity`（你要的那种对话）**功能一直是好的**，只是没有直接的入口。

### 修法

**1. 「开始对话」直接进角色扮演聊天**

```java
findViewById(R.id.btn_cards).setOnClickListener(v -> openRoleplayChat());
```

没有角色时提示并引导去创建，而不是静默跳角色库让人一头雾水。

**2. 手机聊天里的 `···` 改成明确菜单**

原来是"点一下就静默切走"，用户不知道发生了什么。现在是：

```
角色扮演模式（有动作、神态描写）
清空这次对话
查看角色资料
```

## 三、YIJIE 技能：6 → 13

### 新增的七个

| 技能 | 做什么 | 关键约束 |
|---|---|---|
| ✍️ **改写润色** | 把文字改得更好 | 直接给改后的，不先分析 |
| ✉️ **写邮件** | 起草邮件 | 第一行给「主题：」，语气按收件人判断 |
| 📊 **整理成表格** | 杂乱信息结构化 | 缺的信息留空，**不要编** |
| 🔎 **提取要点** | 从长文本抽字段 | 时间/金额/人名**原文照抄** |
| 🎓 **讲解概念** | 从浅到深讲明白 | 先大白话，再类比，再定义 |
| 🐛 **排查问题** | 按线索定位原因 | 每个原因给一条验证方法，**先只问一个问题** |

### 为什么这些约束重要

技能不是"给个名字就行"——它本质是**一段追加到 system 的输出规范**。

举个实际的对比。「整理成表格」如果只写"把信息整理成表格"，模型很容易
**自己补上没给的信息**（比如你没说保质期，它编一个）。所以指令里明确写了
"缺的信息留空或写「—」，不要编"。

实测有效：

```
输入：apple 10 yuan, banana 5 yuan, orange 8 yuan

输出：
| 名称   | 价格 |
|--------|------|
| apple  | 10   |
| banana | 5    |
| orange | 8    |

注意：价格单位统一为「元」，但未说明是否含税或是否有折扣。
```

最后那句是模型主动指出**信息缺口**——这正是指令起作用的地方。

### 技能列表的完整入口

技能在 `···` → 「选择技能」里。**13 个**：写文档、写代码、总结、翻译、
做计划、分析、改写润色、写邮件、整理成表格、提取要点、讲解概念、排查问题。

  但代价是模型可能不严格遵守输出格式。
