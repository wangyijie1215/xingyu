# 语音通话 · TTS

> 对应 `dist/EchoFlow-v3.4-语音通话.apk`（8.02 MB）

---

## 一、这个功能之前是假的

「电话」页一直存在，界面也做得挺像，但 `VoiceCallActivity.speak()` 里
**只有打字机字幕，没有任何音频**：

```java
// 旧实现：一张一张把字贴上屏幕
caption.setText(text.substring(0, i[0]++));
```

所以"打电话"其实是**看字**。现在加了第二条线：字幕照常渐显，
音频同时开播，整句以**音频播完**为准才解锁输入（听比读慢）。

## 二、四个渠道

| 渠道 | 音质 | 前提 |
|---|---|---|
| **本地 TTS 服务** | 最好，322 个神经音色 | 电脑跑 `tools/tts-server.py` |
| OpenAI 兼容接口 | 好，6 个音色 | API Key |
| 自定义 HTTP 端点 | 取决于服务 | SQL 填 URL |
| 手机自带 TTS | 机械音，所有角色同一个声 | 无 |

### 为什么本地服务是首选

`edge-tts` 是 Python 库，手机上跑不了。让电脑跑一个极小的 HTTP 服务
（`tools/tts-server.py`，约 200 行），App 走局域网请求，就能用上
微软的在线神经音色 —— 中文有**晓晓（温柔）**和**晓伊（活泼）**，
日文有**七海**（二次元角色用日语音色反而更贴）。

实测生成的音频：**3.096 秒 / 48 kbps / 有效 MP3**。

### 音色分配

六个内置角色各分到不同音色，这是"她听起来像她"的关键：

| 角色 | 音色 | 理由 |
|---|---|---|
| 月铃 | 七海（日文） | 神秘少女 |
| 艾莲 | 晓晓 | 成熟治愈 |
| 白夜 | 晓晓 | 安静 |
| 爱丽丝 | 晓晓 | 温柔寡言 |
| 洛可 | 晓伊 | 话密 |
| 凛 | 晓伊 | 傲娇、语速快 |

选音色时**会立刻试听**一句 —— 挑音色这件事，看文字描述没用。

## 三、几个设计决定

**1. 括号里的动作不念出来**

角色回复常带 `（把伞往你那边偏了偏）`。这个用 TTS 念出来很出戏，
所以 `TtsSpeaker.strip()` 会把 `（）`、`()`、`**`、`[]`、`「」` 都去掉，
只念真正说的话。

**2. 缓存优先**

同一句只合一次。通话里角色常说的「嗯」「我在」如果每次都请求一次，
延迟会很烦人。按 `音色+语速+音调+文本` 做 key。

**3. 失败必须降级，不能哑掉**

远端连不上时自动退回手机自带 TTS。自带音色机械，
但比"点了没反应"好。**无论走哪条路径，回调都必须被调用一次** ——
否则通话界面会永远卡在"她还在说…"。

**4. 退出就静音**

`onPause` 停掉正在播的那句，`onDestroy` 关掉引擎。
否则退出通话页后声音还在放，很奇怪。

**5. 音色不存进角色卡**

`TtsStore` 单独存一层。理由：音色是**本机设备**上的偏好，
跟着角色卡导出/导入走，换台设备音色名可能不存在，会带一堆无效值。

## 四、踩的坑

**坑 1：`speaker` 字段名冲突**

`VoiceCallActivity` 里已经有一个 `boolean speaker`（免提开关），
我又加了个 `TtsSpeaker speaker`，直接编译不过。
改名成 `tts`，并在注释里写清"别和上面的扬声器搞混"。

**坑 2：默认 `python` 不是你要的那个**

`python -c "import edge_tts"` 报模块不存在，但 `edge-tts.exe` 明明在。
原因是另一个 Python（Doubao 沙箱的 3.14）抢占了 `PATH`：
```
<某个沙箱目录>\python.exe
```
真正装了 edge-tts 的是 `Python311\python.exe`。服务脚本本身没问题，
是**用错了解释器**。

**坑 3：PowerShell 传中文给 HTTP 会炸**

`Invoke-WebRequest` 带中文查询参数时，服务端收到乱码，返回 500。
换成 `curl.exe` 并手工百分号编码就正常（HTTP 200）。
这不是服务端的 bug —— 排查时差点误判成 `parse_qs` 解码问题。

**坑 4：`adb shell cat` 取二进制会坏**

`run-as com.echoflow.chat cat files/tts/x.mp3 > 本地` 得到 0 字节，
`adb exec-out` 也不行。最后用 **base64 中转**才拿到完整文件：
```powershell
adb shell "run-as com.echoflow.chat cat files/tts/x.mp3 | base64" > a.b64
```
验证音频时务必用这个方法，否则会误以为"文件是空的"。

## 六、你这边要做的

**1. 启动 TTS 服务**（每次要用语音时）

```powershell
cd <星语目录>\tools
python tts-server.py
```

注意：如果机器上有多个 Python，**要用装了 edge-tts 的那个解释器**。
直接敲 `python` 可能命中另一个没装依赖的版本（我遇到过，报模块不存在）。
用 `python -c "import edge_tts"` 能先确认。

**2. 真机连接**

- 模拟器：`10.0.2.2:5001`（已验证可用）
- 真机：填电脑的局域网 IP，例如 `192.168.1.100:5001`，
  并确认防火墙放行 5001 端口

和 ComfyUI 一样，服务默认监听 `0.0.0.0` 就行（脚本已经这么设了）。

## 七、没做到的

- **没有语音识别（STT）**。现在"用户说话"仍是打字输入 ——
  要真正对等通话，还需要把录音转文字的链路接上（本机有 whisper 可用）。
- **唇形/动画没有跟音频联动**。`onStart`/`onDone` 回调已经预留，
  但界面还没有"正在说话"的动效。
- **音色列表是内置的 8 个**，不是从 `/voices` 动态拉的。
  服务端接口已经有了（322 个音色全在），但界面只列了常用的几个 ——
  322 个铺在列表里反而难选。
