## 零、先说事故：源码被我自己搞坏了，已修复

这一轮最重要的不是新功能，是我把一个已经能跑的工程弄坏了，又修回来。

### 事故

我想批量把 Java 字符串里的中文引号统一成全角。写了一条正则：

```
(?<=[\u4e00-\u9fff，。：、；])"([^"\r\n]{1,20})"(?=[\u4e00-\u9fff...])
```

**它匹配范围过宽**，把合法代码里的 `", "` 也改了，还把字符串边界的引号吃掉。
一次性改了 37 个文件，然后才发现编译不过。

### 为什么会滚成 100 个错误

| 轮次 | 做法 | 结果 |
|---|---|---|
| 事故 | 一条正则改 37 文件 | 100 错误 |
| 修复 1 | 把 `「, 」` 换回 `", "` | 又动 60 文件，仍 100 错误 |
| 修复 2-4 | 继续用正则补引号 | 每次修对一部分、弄坏另一部分 |
| 修复 5 | 用正则删 `「` 并补 `"` | **17 → 41 错误，更糟** |

**根因**：我在没有版本控制、没有备份的情况下，连续用**未经 dry-run 的正则**改源码。

### 怎么修好的

1. **先建 git 基线** —— 这是第一件该做却一直没做的事
2. **从 v3.0 APK 反编译**，恢复 23 个被改坏的文件
3. **只手工修剩下的 17 个错误**，每修一类就编译一次

17 个错误分 5 类，全是 jadx 的产物，逐一处理：

| 错误 | 根因 | 修法 |
|---|---|---|
| `CapsuleService:62` | `TimeCapsule.this` 引用匿名类外部对象 | 改成实际变量名 `create` |
| `DiaryService:82-84` | 同上 | 改成 `diaryEntry` |
| `LetterService:94-97` | 同上 | 改成 `fallback` |
| `FortuneService:113,132` | jadx 寄存器残留 `r7` / `r13` | 还原为 `iArr[0]` |
| `DiaryActivity:346` | 原始类型 `keySet()` | 显式 `Object` 转换 |
| `SettingsActivity:144` | 给 `final` 赋值 | 去掉 `final` 并单独拷一份给线程 |

**结果：0 错误，BUILD SUCCESSFUL。**

### 我该做而没做的

1. **动手前没建 git** —— 这是第一处、也是最致命的一处失误
2. **改完 37 个文件才编译** —— 应该改一小步就验一次
3. **修复失败后连做 5 轮** —— 第一次修不好就该停下换思路
4. **没做 dry-run** —— 后来写的 `Fix6` 有了预演模式，但那是第五次才想到

**已改进**：现在 `tools/` 下的诊断工具（`OddQuotes`、`Dense`、`Scan`）**全部只读不写**，
真正改文件的工具默认预演、必须显式 `--apply` 才落盘。

## 一、手机里的文档

### 与 YIJIE 菜单里「我的文档」的分工

| | 入口 | 定位 |
|---|---|---|
| YIJIE 的「我的文档」 | 助手菜单 | 从**助手**出发：我让它写的东西 |
| 手机的「文档」 | 手机桌面 | 从**文档**出发：所有文档，可读可改可新建 |

后者才算完整的文档功能 —— 一个能管理、能编辑的地方，而不只是产物列表。

### 功能

- **列表**：文件名、大小、修改时间
- **新建**：右上角 ＋ 输入名字，自动生成 `# 标题` 开头
- **打开**：显示完整 Markdown，**内容可编辑**
- **保存**：写回原文件
- **导出**：写到 `Android/data/com.echoflow.chat/files/docs/`
- **长按**：打开 / 重命名 / 删除

### 实测

```
列表显示 3 篇文档（之前测试生成的）
打开后显示完整 Markdown 正文（含表格、列表、代码块结构）
底部按钮：导出 / 关 / 保存
末尾有「📄 已保存到「我的文档」」回执
```

### 写文档的自动落盘链路

```
YIJIE 选「写文档」技能
   ↓
回复自动检测（有 # 标题 + ≥2 个 ## 小节 + >300 字）
   ↓
存 files/docs/{标题}_{时间戳}.md
   ↓
消息末尾追加回执
   ↓
手机「文档」里能看到、能改
```

用启发式判断"算不算文档"，而不是让模型输出特殊标记 —— 多一个标记就多一个模型可能不遵守的约定。

## 二、漂流瓶

### 文案库

**43 条原创文案，分 5 类**：祝福 / 治愈 / 温暖 / 深夜 / 勇气。

写的时候守了三条规矩：

1. **不说教** —— 不出现「你应该」「你要相信」。被祝福的人不需要被指导，只需要被看见
2. **不空洞** —— 要有具体的物和时刻：等的那班车、晒过的被子、便利店的热柜
3. **不强行正能量** —— 允许承认难过

举几条：

> 你不必今天就振作起来。
> 难过是有权利慢慢走的，它想待多久就待多久。

> 如果今天只完成了一件事，那也算数。吃饭也算。

> 深夜里想的那些事，有一半第二天就不重要了。

> 有些门关上了不是坏事。
> 是你站在那儿太久，而里面一直没有灯。

### 交互

| 操作 | 行为 |
|---|---|
| **捞一个** | 从海里捡，约 1/4 概率捡到**角色扔的** |
| **写一个** | 自己写一句扔进海里 |
| **收藏** | 捞到喜欢的点「收下」 |
| **我扔的** | 看自己扔出去的 |

**角色扔的瓶子是最有意思的部分**：让她写一句话给「一个你永远不会认识的人」。
这是她以自己身份说的，但对着陌生人 —— 比日常对话更容易说出真心话。

### 海面是自绘的

`SeaView` 用 `Canvas` 画，不用任何图片：

- **渐变夜空** + 26 颗闪烁的星
- **月亮**：三层径向渐变光晕 + 球面暗部（不是纯色圆片）
- **月光倒影**：22 条带正弦抖动的光带
- **三层波浪**：不同速度、不同透明度，产生纵深

一个 `ValueAnimator` 驱动相位，`onDraw` 只做路径绘制。

### 实测

```
捞到「深夜」分类的文案，显示完整
按钮：再捞一个 / 放回海里 / 收下
无崩溃
```

## 三、美术升级

### 设计 token 重构

原来的色板已经不错，但有三个问题：**背景层次跨度大**（卡片压在底上显"浮"）、
**正文对比度偏灰**（字看着脏）、**描边深浅不一**。

新版：

| 项 | 旧 | 新 |
|---|---|---|
| 背景夜色阶 | `#07070D` → `#242438` | `#08060F` → `#2C2350`（四级递进） |
| 正文色 | `#ABA6C6` | `#C3BEDB`（对比度提到 ~8:1） |
| 描边 | 6%~10% 不统一 | 统一 8% 白 |
| 新增 | — | `surface` / `overlay` / `danger` 三组语义色 |

**关键改动**：颜色按「用途」命名（`surface`、`bg_page`），不再按「明度」（`ef_night_600`）。
引用处不用再猜"这个该用 500 还是 600"。

### 卡片质感

从「一层实色 + 一圈等宽描边」改成**三层叠加**：

```
第 1 层：渐变描边（顶亮底暗，模拟受光）
第 2 层：实底（内缩 1dp）
第 3 层：顶部高光（中间一段，两端渐隐）
```

圆角从 18dp 提到 20dp。视觉上从"色块"变成"有厚度的卡片"。

### 顶部天幕

首页和角色主页的顶部不再是一块纯渐变，而是：

- 底色：夜色三级渐变
- **左上主色光晕**（径向，模拟一盏灯）
- **右上暖光**（远处的一点光）
- 底部渐隐到页面底色

给页面"空间感" —— 标题压上去时是有纵深的。
