## 一、内置了一首歌

你给的 mp3 是 Google 生成的曲子（带 C2PA 溯源签名），182 秒 / 192kbps / 4.17 MB。

### 处理

```
原文件  4.17 MB / 192kbps
   ↓ ffmpeg -map_metadata -1 -c:a libmp3lame -b:a 96k
内置文件 2.08 MB / 96kbps
```

- **降到 96kbps**：按你选的方案，手机外放听感差异很小，体积省一半
- **`-map_metadata -1`**：把 C2PA 溯源标签和其他元数据全剥掉。
  一是没必要把生成工具的签名打进产品包，二是能省下 6 KB

放在 `res/raw/builtin_song.mp3`。

### 播放器

`MusicPlayer.java` 包了 `MediaPlayer`。

**为什么不用 ExoPlayer**：只有一首本地 mp3，没有播放列表、没有流媒体、没有后台播放。
`MediaPlayer` 是平台自带的，零依赖，够用。引入 ExoPlayer 会增加约 800 KB 包体，
换来的能力一个都用不上。

**生命周期**：`MediaPlayer` 不会自己释放，必须在 `onDestroy` 里 `release()`，
否则每次进出音乐页都会漏一个实例，每个都占着音频解码器。已在
`PhoneAppActivity.onDestroy` 里处理。

## 二、未读角标：一个真 bug，已修

### 你报的现象

「点了新消息还是有红色的 1 未读」

### 根因

看代码就明白了 —— `PhoneHomeActivity.badgeFor()` 原来是：

```java
if ("微信".equals(appName)) {
    int n = 0;
    for (CharacterCard c : CardStore.listCards(this)) {
        if (PhoneStore.count(this, c.id) > 0) {
            n++;
        }
    }
    return n;      // ← 有聊天记录的角色数
}
```

**这个数字统计的是「有多少个角色和你聊过话」，不是「有多少条没读」。**
只要你和她聊过一次，这个数就永远是 1，点进去也不会变 —— 因为它和「读没读」根本无关。

另外 `PhoneListActivity` 里那段更离谱：

```java
if (fromHer && msgs.size() > 1) {
    h.badge.setVisibility(View.GONE);   // 进入会话即视为已读
} else {
    h.badge.setVisibility(View.GONE);   // ← 两个分支一样，纯死代码
}
```

两个分支都设 `GONE`，等于完全没写。

### 修法：已读游标

新增 `ReadCursor`，记录**每个角色你读到第几条**：

```java
未读数 = 她发的消息总数 - 已读游标
```

但要处理一个细节：**只数结尾处连续的、她发的消息**。
如果最后一条是你发的，说明你已经回过了，不该有未读：

```java
for (int i = total - 1; i >= read; i--) {
    if ("assistant".equals(msgs.get(i).role)) {
        n++;
    } else {
        break;   // 遇到用户发的就停
    }
}
```

三处联动：

| 位置 | 行为 |
|---|---|
| `PhoneChatActivity.onResume` | 进会话 → `markRead()` 把游标推到最新 |
| `PhoneListActivity` 行角标 | `ReadCursor.unread()` |
| `PhoneHomeActivity` 图标角标 | `ReadCursor.totalUnread()` |
| `MainActivity` 角色卡 | `ReadCursor.unread()` |

**实测**：

```
进聊天前：月铃卡片显示 1
进聊天后：files/_read_cursor.json = {"builtin_yueling":1}
返回首页：角标消失 ✅
```

## 三、开屏动画

### 编排（总长 1.5 秒）

| 时间 | 元素 | 动作 |
|---|---|---|
| 0ms | 光晕 | 从 0.6 放大到 1.0 + 淡入，之后持续缓慢呼吸 |
| 120ms | 图标 | 从 0.7 弹性放大（`OvershootInterpolator` 给一点回弹） |
| 420ms | 「星语」 | 上浮 26px + 淡入 |
| 600ms | 标语 | 上浮 18px + 淡入 |
| 1050ms | 底部品牌行 | 淡入 |
| 1500ms | 整体 | 淡出 280ms → 进主页 |

用纯 `ViewPropertyAnimator` 实现，不引入 Lottie —— 一个开屏不值得加个依赖。

### 踩了个真坑：Android 12+ 会闪白屏

第一版做了 `windowBackground = splash_bg`（深紫），结果实测**冷启动还是先白一下**。

**原因**：Android 12+ 用 SplashScreen API 接管了启动画面，
**完全忽略 `windowBackground`**，只认 `windowSplashScreenBackground` 和图标。
不显式设置就是白底 + 应用图标 —— 所以白屏。

**修复**：加 `res/values-v31/themes_splash.xml` 单独覆盖：

```xml
<style name="Theme.EchoFlow.Splash" parent="Theme.EchoFlow">
    <item name="android:windowSplashScreenBackground">#170F2C</item>
    <item name="android:windowSplashScreenAnimatedIcon">@drawable/ic_launcher_large</item>
    <item name="android:windowSplashScreenAnimationDuration">0</item>
    <item name="android:windowBackground">@drawable/splash_bg</item>
</style>
```

改完后实测：冷启动直接是深紫底 + 图标，白闪没了。

> 这是「同一份配置在不同 Android 版本上行为不同」的典型 ——
> 只在模拟器（Android 14）上测才能发现。

### 仍然没做到

- **音乐只有一首**：没有播放列表、没有循环/随机、没有后台播放与通知栏控制
- **未读机制简化**：游标记的是「消息条数」，如果删除历史会错位（当前不会删，所以没触发）
- **开屏不能跳过**：固定 1.5 秒，没有「点击跳过」
