## 一、桌宠设置页下方白底

**你报的**：页面下半部分是白的，很难看。

**根因**：`PetSettingsActivity` 里只给内层 `LinearLayout` 设了深色背景，
但外面那层 `ScrollView` **没设背景**。内容不满一屏时，下方露出的正是
ScrollView 自己的背景 —— 而它用的是主题默认色（浅色主题下就是白）。

```java
ScrollView sv = new ScrollView(this);
sv.setBackgroundColor(0xFF0E0A18);   // ← 补的就是这一行
sv.addView(linearLayout);
setContentView(sv);
```

**教训**：给滚动页设背景要设**两层**。这是个很容易漏的点 ——
不滚动的时候看不出问题，一旦内容短于屏幕就露馅。

## 二、球不动时还左右平移

**你报的**：手机不动，它还在左右飘。

**根因**：每帧判断"水平速度是否低于下限，低了就给它补回去"：

```java
if (Math.abs(vx) < MIN_SPEED) {
    vx = (vx >= 0 ? 1 : -1) * (MIN_SPEED + random);   // ← 元凶
}
```

这行的本意是"别让它停下来"，结果是**它永远停不下来**。
每次落地都把速度补回下限，于是球永远在飘。

**修法**：把"防止停住"改成**真正的能量衰减**：

```java
boolean onGround = y + size >= screenH - 2f;
if (onGround && Math.abs(vy) < 120f) {
    vx *= 0.92f;              // 地面摩擦，把水平速度磨掉
    if (Math.abs(vx) < 12f) {
        vx = 0f;              // 足够小就归零，避免亚像素抖动
    }
}
...
if (Math.abs(vy) < 90f) {
    vy = 0f;                  // 竖直方向也不再弹
}
```

顺带加了两个改进：

- **静止降帧**：完全停下后从 60fps 降到 4fps。球不动就没必要每 16ms 重绘一次。
- **拖拽让位**：`dragging` 字段被内层匿名类的同名局部变量**遮蔽**了，
  导致物理线程读到的永远是 `false`，拖拽时物理还在跑、跟手指抢位置。
  删掉那个局部声明就好了。

**验证**：连拍 4 张（间隔 2 秒），**四帧 MD5 完全一致** → 确实停了。

## 三、桌宠改用角色原图

**你报的**：Q 版太丑，不如用原图。

现在 `attachAvatar()` 的逻辑反过来：**优先用角色原图**，
只有连原图都没有时才退回 Q 版缓存。

用原图之后一眼就能认出是谁 —— Q 版虽然"圆润"，但和角色本人不像，
反而丢掉了"这是她"的感觉。

菜单里的「重新生成 Q 版形象」也换成了「回到原位」（拖到屏幕外时恢复用）。

## 四、生图：三个渠道 + 自定义提示词

### 渠道

| 渠道 | 质量 | 前提 |
|---|---|---|
| **本地 ComfyUI** | 最好（Pony V6 XL + 本机 LoRA） | 电脑开着，同一网络 |
| Pollinations | 一般（只有 sana 一个模型） | 什么都不用配 |
| 自定义 HTTP 端点 | 取决于你的服务 | 填 URL 模板 |

ComfyUI 走标准编程调用：`POST /prompt` → 轮询 `/history/{id}` → `/view` 取图。

### 自定义提示词

页面上多了一个输入框，可以直接写；留空就用下方的预设按钮。

### 一路踩的四个坑（这段值得留档）

**坑 1：POST 永远挂起，且不报错**

GET 正常，POST 卡死，`setReadTimeout` 完全不起作用。

**根因**：Android 对较大的 POST 会自动加 `Expect: 100-continue`，
等服务器先回 `100 Continue` 再发正文。这个服务端不回，
于是请求永远停在"发送中" —— 而且这段不受 readTimeout 约束。

**修法**：

```java
conn.setRequestProperty("Expect", "");
conn.setFixedLengthStreamingMode(payload.length);
```

**坑 2：服务端报 `'str' object has no attribute 'shape'`**

节点连线我写成了 `new Object[]{"8", 0}`，但 `org.json` 的
`put(String, Object)` 遇到裸数组会**当成字符串序列化**，
服务端收到 `"[\"8\",0]"` 这样的字符串而不是数组。

**修法**：显式转成 `JSONArray`。

**坑 3：这个错误差点被我自己的代码吃掉**

原来的 `postJson` 把异常吞掉只返回 `null`，调用方只能报一句
"可能是模型名不对"。**真实原因全被埋掉，排查全靠猜。**

改成把失败原因抛出来之后，第一次运行就直接看到了服务端的原始报错，
坑 2 是一眼定位的。**吞异常是排查效率的最大杀手。**

**坑 4：Pony 的质量标记**

生成的图构图崩坏、头被裁掉。原因是 Pony V6 靠
`score_9, score_8_up, score_7_up` 这套**自己的**质量标记选档位，
通用模型的 `masterpiece / best quality` 对它基本无效。

加上这三个标记后是明显不同的一档，再把
`cropped head, head out of frame` 写进负面提示词，构图就稳了。

### 还有一个显示 bug

生成的图是 512×768 竖图，但预览框用了 `CENTER_CROP` 塞进固定尺寸 ——
**从中间裁一块，脸完全看不到**。改成 `FIT_CENTER` + `adjustAspectRatio`。

这个和坑 4 叠加的时候很容易误判成"模型出图有问题"，
实际一半是显示层的锅。

### 实测

```
提交 → 16 秒出图 → 512×768 → 构图完整、有脸、画质高
缓存生效，二次进入秒开
```
