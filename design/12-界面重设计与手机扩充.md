## 一、图标重画

### 前情

上一轮的图标是用 AI 生成的位图直接缩放来的。你指出「中间那图截得不好」——是对的。

**根因**：AI 源图（1254×1254）四周有大片深色留白，图形只占中间约 45%~80% 的不规则区域。
我按「缩放整张图」处理，等于把图形连着留白一起缩小，结果：

- 图形显得小
- 视觉重心偏移（图形本身偏右上，缩完更明显）
- 自适应图标裁切后，边缘的留白被切掉，构图更失衡

### 这次改用矢量重绘

不再缩放位图，而是用 `<path>` 把图形**精确画出来**：

| 文件 | 用途 |
|---|---|
| `drawable/ic_launcher_fg.xml` | 前景（两个气泡 + 四角星），108dp 画布 |
| `drawable/ic_launcher_bg.xml` | 背景（深靛紫径向渐变） |
| `drawable/ic_launcher_mono.xml` | 单色版（Android 13+ 主题图标） |
| `mipmap-anydpi-v26/ic_launcher.xml` | 自适应图标，引用上面三个 |
| `mipmap-*/ic_launcher.png` | 各密度位图（48/72/96/144/192），由 `tools/IconGen.cs` 生成 |

构图：后气泡在左下（淡紫 `#C7A8FF`），前气泡在右上（亮白 `#F4F2FF`），
前气泡的右上角**旋成一个暖橙四角星**（`#FFA657`）——「对话变成记忆」。

### 工具链的坑

`tools/IconGen.cs` 是用 C# 写的，因为 PowerShell 做这件事反复失败：

```
New-Object : Cannot find an overload for "LinearGradientBrush" and the argument count: "4"
Cannot find an overload for "FillRectangle" and the argument count: "2"
[System.Object[]] does not contain a method named 'op_Multiply'
```

PowerShell 对 GDI+ 的重载解析会挑错，而且多行构造参数、`@()` 数组里的乘法都会出问题。

第一次写 C# 时又踩了两个：

1. `Add-Type -TypeDefinition` 会把 `using (var x = ...)` 这种写法处理错（报「不存在名称」），
   即使源码本身没问题 —— 换成 `csc.exe` 编译就好了
2. .NET 4.0 的 `csc` 只支持 C# 4：不能用元组、内插字符串，`var` 在 `using` 里也容易出问题。
   最终写成显式类型 + `try/finally` 的保守风格

**结论**：生成美术资源这类活，直接写 C# 跑 `csc.exe`，别跟 PowerShell 的 GDI+ 较劲。

## 二、移除外层朋友圈

按你的要求，把**首页顶栏的「朋友圈」按钮**和独立的 `PostsActivity` 整个删掉了：

- 删除 `PostsActivity.java`、`activity_posts.xml`、`item_post.xml`
- `activity_main.xml` 移除 `btn_posts`
- `MainActivity` 移除跳转
- `AndroidManifest.xml` 移除注册

朋友圈现在**只存在于手机里**（`PhoneMomentsActivity`），从手机的 Dock 或首页「在手机里看 ›」进入。

> 注意：外层删了，但 `PostStore` 保留 —— 手机里的朋友圈还在用它，
> 而且首页的「最近动态」也要读它。删掉的只是**重复的入口**，不是数据。

## 三、首页重设计

### 问题

旧首页是一个**空聊天框 + 一排按钮**。用户装完打开，看到的是：

```
星语
[朋友圈][角色][新建][grok-2][手机][设置]
月铃 艾莲 洛可 白夜 凛 爱丽丝
              （一片空白）
     在下方输入消息开始对话 ✨
[输入消息，Enter 发送]  [发送]
```

三个问题：

1. **不知道点哪** —— 六个按钮平铺，没有主次
2. **没有信息** —— 空白区域什么都没说
3. **顶栏必然溢出** —— 按钮加到第 6 个时「设置」已经被挤出屏幕了

### 新结构

```
┌──────────────────────────────────┐
│ 星语                          📱 ⋯ │  ← 只留「手机」和溢出菜单
│ 与你有关的，都会被记住              │
├──────────────────────────────────┤
│ 今天                          10:05│
│ 月铃 · 此刻天亮前离开               │  ← 读日程 + 情绪 + 关系
│ 白天找不到她                       │
│ 关系 陌生 · 亲密度 0/100 · 情绪 平静 │
├──────────────────────────────────┤
│ 继续对话                            │
│ ┌────┐┌────┐┌────┐┌────┐          │  ← 头像 + 名字 + 此刻状态 + 未读
│ │月铃││艾莲││洛可││白夜│          │
│ │天亮││开门││开店││看星│          │
│ └────┘└────┘└────┘└────┘          │
├──────────────────────────────────┤
│ 最近动态              在手机里看 ›  │
│ 月铃  今天又下雨了…           3分前 │  ← 朋友圈摘要
├──────────────────────────────────┤
│ [说点什么…        ✨]  [开始对话]   │
└──────────────────────────────────┘
```

新版回答三个问题：**她此刻在做什么 / 我该找谁继续 / 最近发生了什么**。

### 入口收敛

顶栏从 6 个按钮收成 2 个：`📱 手机` + `⋯`。
其余全进 `PopupMenu`：角色库 / 新建角色 / 今日运势 / 日程 / 设置 / 关于。

这正是我在上一轮文档里说的「下一轮该把顶栏换成标题 + 溢出菜单」——
现在做了，而且不是单纯搬按钮：首页本身的信息架构也换了。

### 角色卡的状态点

「继续对话」里的每张卡显示：

- 头像 + 名字
- **此刻在做什么**（来自日程）
- 左上角绿点：在线；她忙的时候**变暗到 35%**
- 未读角标：她最后连发了几条而你还没回

长按角色卡进角色主页，点击直接进聊天。

## 四、手机扩充到 12 个应用

原来 12 个格子里只有 8 个应用。新增 5 个：

| 应用 | 内容 | 是否真能用 |
|---|---|---|
| **相册** | 按角色归档：头像 + 场景图 + 神社图 | ✅ 用真实素材 |
| **音乐** | 她在听的歌（按人设预置 3 首）+ 此刻状态 | ⚠️ 列表真实，播放未接入 |
| **天气** | 角色对天气的评论 | ⚠️ **见下方说明** |
| **备忘** | 她写过但没发出去的话（读日记的 `unsaid`） | ✅ 真实数据 |
| **计算器** | 四则运算 + 括号 + 小数 + 百分比 | ✅ **真的能算** |

### 天气：我选择诚实

第一版我写了「正在读取…」和一个 `—` 的温度占位。这很糟：**它看起来像在加载，实际上永远不会有结果**。

改成了：

> **未接入**
> 还没有接天气数据源，所以这里不显示具体温度。
> 下面是她们在这种天气里会说的话。

编一个假的 `23°C 多云` 比留空更糟——用户会当真。
现在的版本不假装，但角色评论是有价值的（那部分本来就是设计内容，不是数据）。

### 计算器是真算的

`CalcEngine.java` 是一个 150 行的递归下降解析器：

```
12×8        = 96
2+3×4       = 14        ← 优先级正确
(2+3)×4     = 20        ← 括号
10÷3        = 3.3333333333
5%3         = 2
-8+3        = -5
```

**验证方式**：模拟器上计算器的显示是 `TextView`，adb 读不稳；
所以我把同样的算法在桌面用 C# 重写一份（`tools/CalcTest.cs`）跑了 10 个用例，**10/10 通过**。
需要保证正确性的是求值逻辑本身，而不是某个像素。

> 这算是一种妥协：没法从 UI 层验证，就退一步验证纯逻辑。
> 但**不能因此说「计算器已验证」** —— 按键绑定是否接对，仍然只做了目视确认。

### 顺带修的一个布局 bug

计算器第一版按键只占了屏幕上方一小块，下面全空。

**原因**：`calcBody()` 返回的 `LinearLayout` 没有 `layoutParams`，权重为 0；
里面的行虽然写了 `weight=1`，但父容器本身高度不确定，权重就没有分配余地。

**修复**：给 body 显式设 `(MATCH_PARENT, 0, 1f)`，让它先占满剩余高度，
内部再按 `display:1.6 / 每行:1` 分配。其他 app body 也用同样的方式处理。
