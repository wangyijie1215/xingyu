## 一、神社是什么——先说清楚它**不是**什么

它不是一个「抽卡小游戏」，也不是一个独立于角色之外的功能按钮。

**神社是这段关系的时间锚点。**

现有的生命感系统里，「关系」是一个持续变化的数值，「事件」是离散的记忆点。两者之间缺一个东西：
**一个每天都会发生、有仪式感、且角色在场的小事件。** 神社就是这个装置。

它承担三件事：

| 作用 | 机制 |
|---|---|
| 给关系一个**每日节拍** | 每天一次参拜，连续参拜累积 streak |
| 给角色一个**主动开口的合理场合** | 陪你去神社、解读签文、写绘马 |
| 给记忆一个**可检索的时间戳** | 每天的签文写进长期记忆，她以后会提起 |

## 二、每日运势

### 2.1 运签等级

六档：**大吉 / 吉 / 中吉 / 小吉 / 末吉 / 凶**

基础分布（未受任何修正时）：

| 大吉 | 吉 | 中吉 | 小吉 | 末吉 | 凶 |
|---|---|---|---|---|---|
| 5% | 18% | 27% | 25% | 18% | 7% |

对应分项分值区间：

| 等级 | 区间 | 语义 |
|---|---|---|
| 大吉 | 84–100 | 云开月明 · 凡事皆宜 |
| 吉 | 70–92 | 雨过天青 · 宜与人共行 |
| 中吉 | 60–86 | 不急不缓 · 稳中向好 |
| 小吉 | 50–78 | 小有顺遂 · 守之则安 |
| 末吉 | 40–68 | 稍显阻滞 · 后必转晴 |
| 凶 | 26–58 | 今日宜静 · 明日必转 |

> **关于「凶」的设计立场**：陪伴类产品不该制造焦虑。因此「凶」的配色**不用红色**，改用冷静的灰蓝（`#4A5A7A → #8FA6C9`），文案永远是「今日宜静 · 明日必转」，且角色在凶签时**必须提供陪伴**而不是念一段判词。这是硬性约束，写在生成 prompt 里。

### 2.2 六个维度

`恋爱 · 学业 · 健康 · 财运 · 人际 · 灵感`

- 每项 0–100，在等级区间内摆动，并附带一句短判词（如「良缘渐近」「记得留余地」）。
- **恋爱项额外受羁绊加成**：`value += (bond - 50) * 0.16`。你和她越近，这支签的恋爱项就越好看——这不是玄学，是她希望如此。

### 2.3 幸运四件套 + 宜忌

- **幸运物**：从 9 个具象小物里取（银白的小物件 / 一枚旧硬币 / 温热的饮品 …）。刻意具体，因为具体的物件才会被角色在对话里提起。
- **幸运色**：直接复用设计系统的颜色名（紫藤 / 灯火橙 / 蔷薇 / 薄荷 / 天青 / 新芽 / 鸟居朱 / 御守金 / 银白）——配色板内化，视觉自洽。
- **幸运方位 / 数字**：八方、1–9。
- **宜 / 忌**：从池中各取 2 条，全部是**可执行的行为**而非形容词（「与人同行」「深夜做决定」），因为它们会被角色说出口。

### 2.4 缘签

除了通用运势，额外给一条 **「你与这位角色的缘分指数」**：
`bondScore = bond * 0.7 + score * 0.3`，并映射回六档。

它的意义是：**同一张签，对不同角色是不同的。** 换一个角色来参拜，缘签完全不同。

## 三、反刷 与 状态倾斜（两个必须同时满足的约束）

这是一对矛盾的需求，解决方案是**「确定性 + 一次性倾斜」**：

```
1. 结果 = hash(日期 + 角色ID + 固定盐)        ← 保证同一天同一角色结果恒定，刷不出来
2. 在抽签的那一刻，用当前状态倾斜一次：
       shifted = clamp(v + bondBias + omamoriBias + emotionBias)
       bondBias    = (bond / 100) * 0.15         关系越近越吉
       omamoriBias = 佩戴「缘结守」时 +0.06
       emotionBias = 开心/期待 +0.05；悲伤/疲惫 −0.04
3. 抽到后**立刻落库**，之后一律回读，不再重算
```

因此：
- 同一天反复进入神社 → 永远是同一张签（仪式感 + 反作弊）
- 关系变好之后 → 明天的签会更倾向吉（成长可见）
- 佩戴不同御守 → 影响明天的分布（御守有实际作用）

`FortuneService.hash01()` 用 FNV-1a 变体把字符串散列到 `[0,1)`，因此「不可预测但可复现」。

## 四、角色解读——生命感的落点

签文本身只是数据。**真正让人记住的是她怎么念这张签。**

生成约束（写进 prompt，不允许模型自由发挥掉）：

1. 两三句话，口语，**必须带一处动作或神态描写**（用 `（）` 括起）。
2. **必须提到签文里的一两个具体点**（某个分项、或某条宜忌），不许泛泛而谈。
3. 凶 / 末吉时：**禁止说「没关系的」这类安慰套话**。她是个不太会说漂亮话的骑士，要用自己的方式表达「今天我在」——例如提出陪对方做点什么。
4. 吉时：允许克制的高兴，但不许夸张。
5. 不许出戏，不许提「AI」「模型」「签文系统」。

示例（吉 · 熟悉 · 期待）：

> 「……签文说，宜与人同行。」她把签纸折好递还给你，指尖停顿了一下。
> 「那今天，我就跟着你了。反正巡夜也是走路。」

示例（凶 · 熟悉 · 平静）：

> （她把签纸翻过来看了一眼，又翻回去）
> 「……签上说今天宜静。那就别走那条路了。」
> 「我送你回去。到门口就走。」

**解读生成失败时**不阻塞签文展示，退回到一句符合情境的保底话术。

## 五、御守系统

八种，**每一种都真的改变系统的行为**，不是装饰：

| 御守 | 效果 | 实现 | 解锁 |
|---|---|---|---|
| 缘结守 | 羁绊增长 +20% | `bondGainMul: 1.2` | 初始 |
| 心宁守 | 她不容易转负面情绪 | `emotionStabilize: 0.15`（抬高切换置信度阈值） | 初始 |
| 梦见守 | 主动消息概率提升 | `proactiveBoost: 0.12`（加成触发分） | 初始 |
| 学思守 | 每次多记一条 | `memoryExtra: 1` | 连续参拜 3 天 |
| 声守 | 更常发语音 | `voiceChance: 0.25` | 连续参拜 7 天 |
| 影守 | 更常发照片 | `imageChance: 0.2` | 关系达「信赖」 |
| 时守 | 更记得节日与纪念日 | `festivalAware: true` | 连续参拜 14 天 |
| 旅守 | 剧情分支更丰富 | `branchBonus: 1` | 完成一次剧情总结 |

解锁时**自动写入事件簿**（`milestone: true`，羁绊 +2），并附一句她的台词。

> 设计要点：御守是「用长期行为换来的系统级增益」，因此它把「每天来参拜」这件小事和「她的行为发生变化」直接连了起来。

## 六、绘马——愿望进入她的长期记忆

这是整个神社里我认为最有价值的一个设计。

1. 用户在绘马架上写一句愿望。
2. 这条愿望以 `tier: 'relation'`、`grade: 'important_fact'`、`importance 0.72` **写入长期记忆**。
3. 之后的日子里，她在检索记忆时会命中它，并**在合适的时机提起**（例如抽到相关签、遇到相关天气、纪念日临近）。
4. **她也会写绘马**：由 LLM 以她的口吻生成，不超过 18 字，符合「话少、不太会直说」的性格。用户在绘马架看到时算一次「她主动表达」。

示例：

| 作者 | 内容 | 状态 |
|---|---|---|
| 你 | 希望她这次巡夜不要再淋雨了。 | 已被她看见 · 她记下了 |
| 爱丽丝 | 希望旅人明天的答辩顺利。 | 昨天 · 她写的 |
| 你（三天前） | 想和她一起看一次雪。 | 已在 9月14日 被提起 |
| 凛 | 希望今年关东大会不要再碰她。 | 前天 |

第三行是关键：**它证明愿望真的进了她的记忆，并且真的被用上了。**

## 七、连续参拜与七日视图

- `streak`：若上次参拜是昨天则 +1，否则重置为 1。
- 每满 7 天写一条里程碑事件（羁绊 +5），她的台词是：
  > 「……你居然真的每天都来。」（说完自己先转过身去了）
- 「最近七日」柱状图：柱高 = 签运等级，颜色 = 等级色，今日柱带发光。
  下方一行汇总裁剪自她的口吻：**「有起有落才正常。」**

## 八、角色日记——「她在你没看的时候也在生活」

聊天是「你找她」。日记是「她自己过日子」。这是性价比最高的生命感装置。

### 8.1 四段固定结构

| 段 | 内容 | 要求 |
|---|---|---|
| `LINE` | 今天的开场 | 一句**具体有画面**的话。禁止「今天天气很好」这类空话 |
| `BODY` | 发生了什么 + 她当时的反应 | 2–3 句，要有细节，禁止总结 |
| `UNSAID` | ★ **她没说出口的那句话** | 只有日记里才写。这是题眼 |
| `TOMORROW` | 明天打算做的一件小事 | 可被次日的主动消息引用 |

生成 prompt 明确要求：允许语句不完整、允许省略号，人写日记不会文绉绉；不许写「亲爱的日记」。

### 8.2 完整示例

> **2026年9月17日 · 夜 · 小雨**
>
> 今天下雨了。
>
> 巡夜走到旧城区的时候，看见那家店的灯还亮着。以前我从来不会注意这种事。……大概是因为有人在旁边指着说「你看」。
>
> 明天要把披风补一下，肩上的线松了。

她的性格是「话少、不太会直说」，所以 **BODY 里没有一句直接的情感表达**。情感全部压在 `UNSAID` 里——这就是设计意图：**用户读到没说出口的那句话时，才真正感觉到她是一个有内心的人。**

### 8.3 心情曲线

`DiaryService.moodCurve()` 把情绪历史按天聚合，值 = 该天主导情绪的积极度 × 100，颜色取情绪语义色。

页面文案不做结论，只给一个观察：

> 从 9月12日 那场雨开始，「期待」出现的频率明显变高了。

### 8.4 用户可以「替我写今天的日记」

生成后允许编辑再保存（`author: 'user'`）。这条路径的意义是：**给用户一个替她表达的机会**——很多人会想留下自己的版本。

## 九、纪念日倒数（附带新增）

把「时间感知」从「知道今天是几号」升级为「她记得那些对你重要的日子」。

```ts
interface Anniversary {
  kind: 'met' | 'birthday' | 'festival' | 'custom' | 'milestone';
  date: string;            // 每年重复的用 MM-dd
  repeatYearly: boolean;
  remindDaysBefore: number; // 提前多少天开始由她提起
  mentioned: boolean;       // 她是否已经在对话中提过
}
```

首页「即将到来的日子」横向轨道，示例：

| 倒数 | 标题 | 副标题 |
|---|---|---|
| 2 天 | 相识 40 天 | 9月19日 · 她说想一起过 |
| 8 天 | 中秋 | 9月25日 · 已列入主动消息 |
| 12 天 | 她的生日 | 9月29日 · 银月骑士团授勋日 |

**与主动性系统联动**：`AnniversaryService.reminderBoost()` 把纪念日转成主动消息的触发分加成（当天 +0.25，提醒窗口内 +0.12），`todayHint()` 的输出直接进入 Prompt 的 `【今日】` 段。这样她提起纪念日不是随机，是被调度的。

## 十一、与既有系统的接线点

```
                         ┌─── 神社（新增）─────────────────┐
                         │  每日签文 → 写入长期记忆        │
时间感知 ────────────────┤  连续参拜 → 事件簿里程碑        ├──→ 关系（+1/天 · 缘结守 ×1.2）
（当前日期/节日）          │  绘马愿望 → relation 层记忆     │
                         │  御守 → 修改系统行为            │
                         └──────────────┬─────────────────┘
                                        │
纪念日倒数 ──► 主动性触发分加成 ─────────┤
                                        ↓
情绪状态机 ◄──── 角色解读 / 日记的情绪快照
                                        ↓
                              角色日记 → 「她没说出口的话」→ 回忆卡
                                        ↓
                        朋友圈（她会发今天的动态）· 聊天（她主动提起）
```

- **神社 → 记忆**：签文、绘马、日记全部落库，可被后续对话检索。
- **神社 → 关系**：每日参拜 +1（缘结守 ×1.2），连续 7 天里程碑 +5。
- **神社 → 主动性**：纪念日 boost、梦见守 boost、签运为凶时她会更主动（担心你）。
- **神社 → 角色主页**：角色主页快捷五宫格可加「神社」入口；她的立绘按当天签运切换表情差分（吉 → `alice-happy`，凶 → `alice-sad`）。
- **日记 → 回忆卡**：`MemoryCardFactory.fromDiary()` 把一篇日记直接变成一张星念卡，标题是
  **《2026.09.17 · 她没说出口的那句话》**。

## 十二、数据模型补充

```ts
interface Fortune {

interface ShrineState {
  characterId: string;
  streak: number; lastVisit: string; totalVisits: number;

  history: Array<{ date: string; rank: FortuneRank }>;

interface Ema {
  characterId: string; text: string; author: 'user' | 'character';
  seenByUser: boolean; mentioned: boolean; mentionedAt?: number;

interface DiaryEntry {
  characterId: string; date: string;
  emotion: string; weather: string; bond: number;
```
