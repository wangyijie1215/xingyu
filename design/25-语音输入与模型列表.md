## 一、语音输入（说话 → 文字）

### 默认走手机自带，不折腾

用户问「手机没有自带的吗」—— **有，而且这才是首选**：

| 方案 | 优点 | 缺点 |
|---|---|---|
| **手机自带**（默认）| 零配置、离线可用、不用 key | 中英混说和专有名词一般 |
| 本地 whisper | 识别最准，完全不出本机 | 要开电脑，装几百 MB 模型 |
| 阿里云百炼 | 国内直连 | 按量计费 |
| OpenAI 兼容 | 中转站开了就能用 | `grok-heavy` 分组没挂 whisper 渠道 |

所以我做了**四渠道可切换**，默认手机自带。不满意再去设置里换。

### 交互

- 点麦克风 → 弹「正在听…」+ 音量条
- 说完自动结束
- **文字填进输入框，不自动发送** —— 语音识别难免错字，自动发送会让人措手不及
- 浮层上可取消

### 接入了三个地方

| 页面 | 说明 |
|---|---|
| 角色扮演 | 新加了麦克风按钮（原来没有）|
| 手机微信 | 原来点了弹「待接入」，现在真能用 |
| 通话页 | 同上 |

### 踩的坑

**1. `lambda` 与反编译残留撞名**

`CardChatActivity` 是从 APK 反编译的，里面已经有 `lambda$onCreate$0` 这类
**编译器合成名**。我加一个新的 lambda，javac 合成的名字和它冲突：

```
错误: 名称与 compiler-synthesized 冲突
```

改成**匿名内部类**就好了。

**2. 模拟器没有麦克风 —— 测不了**

授权流程验证通过（弹出「Allow 星语 to record audio?」），
但识别服务报 `not connected to the recognition service`。

查下来是这样：

```
Input device: 0 (AUDIO_DEVICE_NONE)
```

**模拟器根本没有音频输入设备**，这是环境限制。
真机上才能测出实际识别效果 —— 这一点我不能说"验证过了"。

## 二、生图渠道：模型列表自动拉取

### 解决的问题

模型名是手填的，填错只会得到一个含糊的报错。
而且中转站的模型**说变就变** —— 这次实测就遇到：

- `grok-2` 已下线（你原来填的）
- `grok-4.20-0309-reasoning` 新上线

### 做法

在生图渠道配置里加了「⟳ 拉取模型列表」：

1. 调 `/v1/models` 拿全量
2. 按名字粗筛画图类（含 `image` / `imagine` / `dall` / `flux` / `diffusion`）
3. 弹列表让用户点选，直接填进模型名那一格

### 实测很有用

拉下来一眼就看到问题：

```
✓ 发现 7 个模型，其中 1 个可能用于画图
```

点开列表是 `grok-imagine-image-2.0` —— 但用它仍然报
`No available channel for model ... under group grok-heavy`，
**说明这个分组确实没挂画图渠道**，而不是模型名写错。

**这就是这个功能的价值**：把"猜模型名"和"服务端没开"这两件事区分开。

## 五、还没做到的

**这一版有一条我没能验证：实际语音识别效果。**

原因写在上面 —— 模拟器没有麦克风。我不说"验证过了"，
你装到真机上试一下，如果识别不准，可以在「语音」设置里换成
本地 whisper（装 `faster-whisper` 后跑 `tools/stt-server.py`）。

1. 老配置体系 `ChatStore` 调用点未迁移完（靠双写一致）
2. `EfActivity` 基类建了但没改造老的 29 个 Activity
3. `PhoneAppActivity` 986 行，该拆
4. 桌宠不避让图标、重启不自动恢复
5. `SttProvider` 里的阿里云/OpenAI 渠道写了实现但**没实测**
   （手机自带那条走的是 `VoiceInput`，不经过 `SttProvider`）
