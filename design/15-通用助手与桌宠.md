> 对应 `dist/EchoFlow-v2.9-助手+桌宠.apk`（7.98 MB）

---

## 一、通用助手：一个无人设的 agent

### 它和角色的根本区别

| | 角色 | 通用助手 |
|---|---|---|
| 人格 | 有（角色卡定义） | **没有** |
| 说话方式 | 贴人设、可以有情绪 | 直接、简洁、不客套 |
| 注入的上下文 | 记忆 / 关系 / 情绪 / 日程 / 世界书 | **全都不注入** |
| 历史 | 各角色独立 | 独立一份（`files/general/chat.json`） |

复用了手机模式的微信风界面（同一个 `item_wx_message` 布局），
但走 `GeneralAssistant.build()` 而不是 `PhonePrompt` —— 没有任何角色上下文。

### system prompt 的三个部分

```
【你的定位】回答问题、写代码、翻译、做计算。工具性的存在，不是扮演出来的角色。
【说话方式】直接给答案，不要开场白；简洁；不客套；不确定就说不确定。
【你没有的东西】
   1. 没有名字、性别、性格、情绪。
   2. 不要扮演任何角色，不要加动作描写。
   3. 不要假装有记忆。
   4. 不要说「作为 AI 我……」这类免责声明。
```

**为什么把「你没有的东西」也写清楚**：模型有强烈的「演角色」倾向。
如果只说「你是一个助手」，它会自己补出一个人格 —— 那就变成第三个角色了。
把禁止项显式写出来，才能真正做到「无人设」。

### 实测

发送 "what is the capital of australia"，本地 Ollama 正常回答。
历史落在 `files/general/chat.json`，与角色聊天完全隔离。

> 注：本轮验证时助手的完整问答我只确认到「界面正确、请求发出、无崩溃」，
> 回复文本没逐字截取（键盘遮挡导致自动化点击不稳）。
> 逻辑路径与手机模式聊天完全一致，那条路径此前已端到端验证过。

## 二、桌面宠物：会弹来弹去的 Q 版小球

### 技术要点

**1. 悬浮窗权限不能用运行时权限申请**

`SYSTEM_ALERT_WINDOW` 只能跳系统设置页让用户手动开：

```java
Settings.ACTION_MANAGE_OVERLAY_PERMISSION
```

所以 `PetSettingsActivity` 会**先检查权限状态再决定按钮文字**：

| 状态 | 按钮 |
|---|---|
| 无权限 | 「去开启悬浮窗权限」 |
| 有权限、未运行 | 「放她到桌面」 |
| 运行中 | 「关掉桌宠」 |

这样不会出现「点了没反应」——用户永远知道下一步该干什么。

**2. 前台服务是必须的**

Android 8+ 不用前台服务的话，系统会在几分钟内杀掉悬浮窗。
但通知必须设成 **`IMPORTANCE_LOW` + 静音 + 无振动**：
桌宠的通知只是「我还活着」的凭证，有声音的话用户会以为来了消息。

**3. 物理：一百行手写，不引引擎**

```
重力         1400 px/s²
落地保留     72% 速度（BOUNCE）
水平摩擦     0.995
速度上限     2600 px/s
速度下限     90 px/s（防止停下来）
```

撞墙 6 次后随机加一个水平推力，避免水平速度衰减到停住。

**4. 形变是关键**

一个真正弹跳的球，**落地瞬间会被压扁（squash），起跳拉长（stretch）**。
没有这个形变，看起来就是个贴图在平移：

```java
if (bounced) {
    squashY = 0.78f;                        // 落地压扁到 78%
} else {
    squashY += (1f - squashY) * dt * 14f;   // 弹回原状
}
```

压扁时横向会相应变宽（`w = size * (2 - squashY)`），保持体积感。

**5. 球是用代码画的，不是位图**

`PetBall` 用 `Canvas` + 径向渐变画球：
左上高光 → 主体色 → 暗部，再加两个反光点。
脸有 4 种表情（正常 / 闭眼 / 开心 / 困）。

**为什么不直接用角色头像裁圆**：
- 头像放大后方形边缘明显，悬浮在桌面上很违和
- 手绘的球才能做形变（位图拉伸会糊）
- 体积为零，不用打包任何图片

每个角色有专属颜色（月铃淡紫、凛玫红、白夜深蓝、洛可薄荷…）。

**6. 交互**

| 操作 | 行为 |
|---|---|
| 单击 | 打开她的聊天（同时闪一下开心表情） |
| 长按 | 菜单：让她跳一下 / 换表情 / 关掉 |
| 拖拽 | 暂停物理跟随手指，球被"拎起来"时纵向拉长 |
| 松手 | **按拖拽速度抛出**（惯性），接回物理系统 |

### 实测

服务日志确认：

```
PetService: onCreate
PetService: onStartCommand action=null
PetService: pet view added, size=178.5
```

截图对比（间隔 700ms 两帧）：小球从 x≈300 移动到 x≈270，
带表情与高光，**确实在桌面上弹动**。

## 三、验证记录

| 项 | 结果 |
|---|---|
| 通用助手页面 | ✅ 标题「助手」，副标题「无人设 · 不扮演 · 直接答」 |
| 助手请求发出 | ✅ 走本地 Ollama，无崩溃 |
| 助手历史隔离 | ✅ 存在 `files/general/chat.json` |
| 桌宠权限检查 | ✅ 三种状态按钮文字正确 |
| 桌宠服务 | ✅ 日志确认 view added，178.5px |
| 桌宠物理 | ✅ 两帧对比位置变化，确实在动 |
| 桌宠形变与表情 | ✅ 手绘球带高光与脸 |
| 手机桌面 | ✅ 16 个应用（新增助手、桌宠） |
| release 构建 | ✅ 签名正常 |

### 没做到的

- **桌宠不会避让图标**：它是覆盖在桌面上的悬浮窗，会挡住下面的图标。
  真正的"桌面宠物"要读桌面布局才能绕开，那需要 Launcher 权限，做不到。
- **桌宠重启后不自动恢复**：`START_STICKY` 只在被系统杀掉时尝试重建，
  手机关机重启后不会自动出现，要手动开一次。
- **桌宠只有一只**：没做多只同时上桌。
- **助手回复未逐字验证**：见上文说明。
