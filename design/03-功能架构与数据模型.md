# EchoFlow 功能架构与数据模型

> 对应需求 §33 插件架构 / §34 Provider / §35 模型路由 / §36 上下文 / §53 生命感核心链路

## 一、模块边界

每个模块是一个独立服务，通过接口通信，**互不 import 实现**。新增模型服务只需注册新实现，不改业务层。

```
core/
  ├── character/    CharacterRepo     角色卡 CRUD + 版本管理 + 导入导出
  ├── persona/      PersonaRepo       用户设定
  ├── chat/         ChatRepo          会话 / 消息 / 分支树
  ├── memory/       MemoryService     提取 · 去重 · 分级 · 检索 · 注入
  ├── relation/     RelationService   羁绊值 · 等级 · 成长来源
  ├── emotion/      EmotionService    情绪状态机
  ├── event/        EventService      事件簿 + 回忆卡
  ├── story/        StoryEngine       世界观 / Lorebook / 分支 / 回溯 / 总结
  ├── proactive/    ProactiveService  主动消息调度与限流
  └── context/      ContextManager    token 预算 · 压缩 · 锁定

provider/                              ← 全部为接口 + 可插拔实现
  ├── llm/          LlmProvider       OpenAI-compatible / Grok / 本地
  ├── tts/          TtsProvider
  ├── stt/          SttProvider
  ├── image/        ImageProvider
  ├── search/       SearchProvider
  └── tool/         ToolRegistry      Tool Calling + 自定义工具

platform/
  ├── storage/      SqliteRepo + FileRepo
  ├── secure/       SecureStore       HUKS / Asset（Android: Keystore）
  ├── notify/       Notifier          HarmonyOS 通知 / 服务卡片
  ├── system/       Clock · Weather · Locale（时区/节日）
  └── backup/       BackupService     导出 / 导入 / 迁移
```

**依赖方向**：`platform ← provider ← core ← ui`。core 不感知具体 Provider，只持有接口引用；`LlmProvider.supports(feature)` 决定 UI 是否出现对应能力（不支持则隐藏，不置灰）。

## 二、模型路由

```ts
interface ModelRoute {
  chat:      ProviderRef;   // 对话与角色扮演
  summarize: ProviderRef;   // 上下文压缩、剧情总结
  analyze:   ProviderRef;   // 记忆提取 / 关系 / 情绪 / 事件判定（建议用便宜模型）
  image:     ProviderRef;
  tts:       ProviderRef;
  stt:       ProviderRef;
}
```

默认策略：`chat` 用主力模型（Grok），`analyze` 与 `summarize` 用低成本模型，`image` / `tts` / `stt` 各自独立。这样高频的「分析」调用不会烧掉主力模型的额度。

### 3.2 Memory

```json
{
  "id": "mem_0183",
  "character_id": "char_alice",
  "tier": "long",                     // short | mid | long | relation
  "content": "你喜欢诗歌，尤其是下雨天读的那一类。",
  "importance": 0.86,                 // 0~1
  "grade": "important_fact",          // core_identity | strong_preference | important_fact | meaningful | general | trivial
  "keywords": ["诗歌", "下雨天", "阅读"],
  "source": { "chat_id": "chat_01", "message_id": "msg_4021", "ts": 1789648400000, "excerpt": "我小时候一直住在江边……" },
  "locked": true,
  "disabled": false,
  "hit_count": 7,
  "created_at": 1789648400000,
  "last_used_at": 1789900000000
}
```

**分级与去重**：`grade=trivial` 或 `importance<0.25` 直接落 `short` 并在 7 天后清理；同 `character_id` 下与既有记忆余弦相似度 > 0.88 时合并（保留高 importance、累加 hit_count、更新 source）。

**检索**：`score = 0.5*importance + 0.3*keyword_match + 0.2*recency_decay(last_used_at)`，取 Top-K（默认 12）。

### 3.3 RelationshipState

```json
{
  "character_id": "char_alice",
  "bond": 72,
  "level": "熟悉",
  "level_index": 2,
  "level_thresholds": [0, 20, 40, 60, 80, 95],
  "sources": { "chat": 48, "event": 16, "gift": 5, "moments": 3 },
  "last_delta": 2,
  "met_at": 1786900000000,
  "updated_at": 1789648400000

```

规则：单次对话增量 `0~5`，普通对话 1、深入对话 2~3、特殊时刻 4~5。**UI 只在 `last_delta != 0` 时显示一行提示**；跨等级时额外触发一次轻量动画与事件写入。

### 3.4 EmotionState

```json
{
  "character_id": "char_alice",
  "current": "期待",
  "prev": "平静",
  "valence": 0.42,
  "arousal": 0.61,
  "since": 1789648000000,
  "history": [{ "emotion": "孤独", "from": 1789500000000, "to": 1789648000000 }]
}
```

10 态枚举：`平静 / 开心 / 悲伤 / 期待 / 孤独 / 害羞 / 紧张 / 惊讶 / 生气 / 疲惫`。
**不是随机值**：由 `对话上下文 + 角色设定 + 记忆 + 时间 + 天气` 推导；仅当新判定的置信度 > 0.6 且与当前不同才切换，并写入 history。情绪影响：语气、回复长度（±30%）、标点密度、是否启用颜文字/动作补白、TTS 的 emotion tag、是否触发主动消息。

### 3.6 Chat / Message / 分支树

```json
{
  "chat_id": "chat_01",
  "character_id": "char_alice",
  "character_version": "1.2",
  "card_snapshot": { "...": "创建该会话时的角色卡快照，保证旧聊天不被新版本改写" },
  "persona_snapshot": {},
  "world_ids": ["world_silvermoon"],
  "branch": { "id": "main", "parent": null, "parent_message_id": null },
  "created_at": 1786900000000,
  "last_message_at": 1789648400000
}
```

消息带 `variants: Message[]`（swipe 多答案）与 `active_variant: 0`，因此**重新生成不会覆盖旧答案**。回溯（§14）实现为：以目标消息为 `parent_message_id` 新建分支 `branch.id`，原分支完整保留，分支树由 `branch.parent` 串联。

### 3.7 Lorebook（World Info）

```json
{
  "id": "lore_silvermoon",
  "name": "银月城",
  "entries": [
    {
      "keys": ["银月骑士团", "骑士团"],
      "content": "银月城的守夜武装，成员以银白色披风为记……",
      "insertion_order": 1,
      "position": "before_char",
      "case_sensitive": false,
      "constant": false,
      "priority": 10
    }
  ]
}
```

触发：对本轮 `user_input + 最近 N 条上下文` 做关键词匹配（大小写不敏感、支持子串），命中的条目按 `insertion_order` 注入到角色设定之前，`priority` 高者优先，**总注入预算默认 1200 token**，超出按 priority 截断。`constant: true` 的条目每轮都注入。

### 3.8 ProactiveMessage（主动消息）

```json
{
  "id": "pm_2201",
  "character_id": "char_alice",
  "created_at": 1789640400000,
  "trigger": "weather_rain+memory_rain+event_rainy_night+idle_3d",
  "text": "今天下雨了。突然想起上次和你聊到很晚的那天。你今天呢？",
  "voice": null,
  "read": false,
  "delivered_via": "inapp"
}
```

触发因子（加权求和超阈值才发）：空闲时长、当前时间（是否在作息内）、天气变化、未完成剧情、纪念日、情绪状态、关系等级、近期对话密度。
限流：全局开关 → 单角色开关 → 每日上限（默认 5）→ 勿扰时段（默认 23:30–07:30）→ 仅 Wi-Fi → 主动程度滑杆（克制↔黏人，映射为触发阈值）。

## 四、生命感核心管线（§53）

```
Character Card ─┐
Persona ────────┤
World / Lore ───┤  (关键词触发注入)
Memory (Top-K) ─┤
Relationship ───┤
Emotion ────────┤
Current Time ───┤  (日期/星期/时区/节日)
Weather ────────┤  (授权后)
Scenario ───────┘
        ↓  ContextManager 预算裁剪
     System Prompt
        ↓
     LlmProvider (SSE)
        ↓
     AI Response  ──→ 流式渲染到 UI
        ↓ (流结束后，异步)
   StateAnalyzer: 记忆提取 / 事件检测 / 关系更新 / 情绪更新 / 一致性检查
        ↓
   落库 → 触发一次 UI 轻提示 → 可能生成朋友圈动态 → 可能解锁回忆卡
```

### 4.2 状态分析器输出契约（严格 JSON）

```json
{
  "memories": [
    { "content": "用户童年与江边生活有关。", "importance": 0.74, "grade": "important_fact", "keywords": ["江边", "童年"] }
  ],
  "relation_delta": 2,
  "emotion": { "name": "期待", "confidence": 0.71 },
  "event": { "title": "雨夜一起回家", "body": "第一次共用一把伞。", "milestone": true, "bond_delta": 5 },
  "consistency": { "character_ok": true, "world_ok": true, "timeline_ok": true, "issues": [] }
}
```

约束（已写入 Prompt）：`只提取真正重要、值得长期记住的信息。普通寒暄、日常琐事不要记忆。` / `只有当这次对话发生了值得记录的重要事情时才填，否则填 null。` / `只输出 JSON，绝对不要输出解释、markdown 代码块或其他文字。`
解析失败时：先剥离 ```json 围栏重试一次，仍失败则丢弃本次分析并记一条本地日志（**绝不因此让回复失败**）。

## 五、上下文管理（§36 / §37）

```ts
interface ContextBudget {
  max: number;            // 模型上限，默认 128000
  reserveForReply: number;// 2000
  layers: {
    system:   { weight: 1.0, lock: true  },  // 角色设定 + 世界观
    memories: { weight: 0.9, lock: true  },  // 长期记忆 Top-K，可锁
    summary:  { weight: 0.6, lock: false },  // 前情提要
    recent:   { weight: 1.0, lock: false },  // 最近 N 条原文
    locked:   { weight: 1.0, lock: true  },  // 用户手动锁定的消息
  };
  compressAt: 0.75;       // 达 75% 触发压缩
}
```

压缩流程：保留 `system + memories + locked` → 把最旧的对话滚动总结为「前情提要」段落 → 用 `summarize` 模型增量更新摘要（非重新生成）→ 摘要以 `[前情提要]` 前缀置于 recent 之前。
`user` 端显示：聊天顶栏的 `当前上下文 18,420 / 128,000` 与「自动总结旧消息」开关；超阈值时进度条转橙并提示。

## 六、Tool Calling（§31 / §32）

```ts
interface Tool {
  name: string;                    // weather
  description: string;             // 查询天气
  parameters: JsonSchema;          // { city: string }
  requires: ('network'|'location'|'filesystem')[];
  run(args: any, ctx: ToolCtx): Promise<ToolResult>;
}
```

内置：`search` / `calc` / `python` / `image_gen` / `file_read` / `calendar` / `weather` / 自定义 HTTP。
角色卡通过 `extensions.echoflow.skill_ids` 声明可用工具子集。
**能力协商**：`LlmProvider.supports('tools')` 为 false 时，UI 中「角色技能」区块整块隐藏，并在系统提示中移除工具说明段——绝不向模型发送它无法处理的工具定义。

## 七、数据与隐私（§45 / §46 / §47）

- **默认本地优先**：聊天、Persona、记忆、角色卡、事件、图片全部只落本地 SQLite + 文件目录，不上传。
- **API 请求最小化**：只发送完成当前功能所必需的内容（当前对话窗口 + Top-K 记忆 + 命中的 Lore），不发送全部历史。
- **API Key**：HarmonyOS 用 `@ohos.security.asset`（Android 用 Keystore）；**永不进入备份与导出**。
- **「发送给 AI 的内容预览」**：高级模式下可查看即将发出的完整请求体（含 system prompt 与注入的记忆条目标记），满足可解释性诉求。
- **备份结构**：

```
EchoFlow-Backup-20260917/
├── Characters/      角色卡 JSON + PNG + 立绘
├── Personas/
├── Chats/           按 character_id 分目录，含分支树
├── Memories/
├── Events/          含回忆卡与图片引用
├── Images/          生成图与角色照片
└── Settings/        Provider 配置（**剔除 API Key 字段**）· 主题 · 主动消息规则
```

导入时若目标已存在同 `character_id`，走版本管理而非覆盖：旧版本保留，聊天记录继续引用其创建时的 `card_snapshot`。

## 八、通知与系统集成（§49 / §50）

- 通知内容 = 主动消息正文；点击直达 `chat/{character_id}`。
- 分级控制：全局关闭 → 单角色关闭 → 勿扰时段 → 仅 Wi-Fi → 每日数量上限。
- HarmonyOS 侧：桌面快捷方式（`shortcuts`）+ 服务卡片 + 卡片点击直达角色，卡片内容由 `form_config` 提供（显示头像、名字、当前情绪、最近一条主动消息）。

## 九、全局搜索（§48）

统一索引表 `search_index(kind, ref_id, character_id, text, ts)`，`kind ∈ {character, chat, message, memory, event, card}`。
搜索「江边」返回：2 条记忆、1 段聊天片段、1 个事件、1 张回忆卡——结果按 kind 分组，命中片段高亮，点击跳转至对应详情并定位到消息。
索引在写入时同步维护（FTS5 / HarmonyOS 关系型数据库全文检索），不额外做全量扫描。
